# 08 — สถานะใบเคลมและ State Machine (Claim Lifecycle)

> **กลุ่มผู้ใช้:** IT Staff / IT Administrator | **เวลาอ่าน:** ~6 นาที

---

## สถานะของใบเคลม (Claim Status)

เพื่อความเป็นระเบียบและตรวจสอบย้อนหลังได้ตามมาตรฐาน ISO/IEC 27001 ระบบ ClaimIT ควบคุมการเปลี่ยนสถานะของใบเคลมผ่าน **State Machine (Finite State Transitions)** ที่เข้มงวด ทั้งในระดับฐานข้อมูลและหน้าจอผู้ใช้งาน

---

## แผนภาพวงจรสถานะใบเคลม (State Machine Diagram)

```text
                 ┌───────────┐
                 │   DRAFT   │─────────────────────────────► [CANCELLED]
                 └─────┬─────┘
                       │
             ┌─────────┴─────────┐
             ▼                   ▼
        ┌─────────┐        ┌────────────┐
        │ VIABLE  │        │ NOT_VIABLE │──► [CANCELLED]
        └────┬────┘        └────────────┘
             │ (CONFIRMED, CANCELLED)
             ▼
        ┌───────────┐
        │ CONFIRMED │──────────────────────────────────────► [CANCELLED]
        └─────┬─────┘
              │
              ▼
        ┌───────────┐
        │ SUBMITTED │──────────────────────────────────────► [CANCELLED]
        └─────┬─────┘
              │
     ┌────────┴────────────────────┐
     ▼                             ▼
┌─────────────────┐           ┌──────────┐
│ VENDOR_RESPONSE │──────────►│ RETURNED │──► [CLOSED]
└────────┬────────┘           └──────────┘
         │ (CANCELLED)
         ├──────────────────────────────────► [CANCELLED]
         │
    ┌────┴────┐
    ▼         ▼
┌────────┐ ┌──────────┐
│RETURNED│ │ REJECTED │──► [CLOSED]
└───┬────┘ └──────────┘
    │
    ▼
┌───────────┐
│  CLOSED   │  (สถานะสิ้นสุด)
└───────────┘
```

> **หมายเหตุ:** `CANCELLED` เป็นสถานะสิ้นสุดเช่นกัน — เมื่อยกเลิกแล้วไม่สามารถย้อนกลับได้ สถานะที่อนุญาตให้ยกเลิก: `DRAFT`, `VIABLE`, `NOT_VIABLE`, `CONFIRMED`, `SUBMITTED`, `VENDOR_RESPONSE` (แต่ **ไม่สามารถยกเลิก** `RETURNED`, `REJECTED`, หรือ `CLOSED` ได้)

---

## ตารางอธิบายความหมายและตัวบ่งชี้สี (Status Badges)

| สถานะ | สีป้าย (Badge) | ความหมายและสิ่งที่ต้องทำ | สถานะถัดไปที่อนุญาต |
|---|---|---|---|
| `DRAFT` | สีเทา | ร่างใบเคลม ยังไม่ได้คำนวณคะแนนความคุ้มค่า | `VIABLE`, `NOT_VIABLE`, `CANCELLED` |
| `VIABLE` | สีฟ้าสดใส | ผ่านเกณฑ์ประเมิน (Score $\le 5.0$) คุ้มค่าส่งซ่อม | `CONFIRMED`, `CANCELLED` |
| `NOT_VIABLE` | สีส้มอมแดง | ไม่คุ้มค่าส่งซ่อม (Score $> 5.0$) แนะนำจำหน่าย | `CANCELLED` |
| `CONFIRMED` | สีน้ำเงินเข้ม | ตรวจสอบความถูกต้องและอนุมัติรอส่ง Vendor | `SUBMITTED`, `CANCELLED` |
| `SUBMITTED` | สีเหลืองอำพัน | ส่งเครื่องให้ Vendor แล้ว (Pending Pickup) | `VENDOR_RESPONSE`, `RETURNED`, `CANCELLED` |
| `VENDOR_RESPONSE` | สีส้มอิฐ | ศูนย์บริการกำลังซ่อม (In Repair / Waiting parts) | `RETURNED`, `REJECTED`, `CANCELLED` |
| `RETURNED` | สีเขียว | ศูนย์ส่งเครื่องคืนมาถึงโรงพยาบาลแล้ว ตรวจรับสำเร็จ | `CLOSED` |
| `REJECTED` | สีแดงสด | ศูนย์ปฏิเสธการเคลม (เช่น เครื่องตกน้ำ/หมดประกัน) | `CLOSED` |
| `CLOSED` | สีเขียวมรกต | ปิดงานเคลมสมบูรณ์ ครุภัณฑ์กลับเข้าคลัง/ใช้งาน | *(สถานะสิ้นสุด ไม่สามารถเปลี่ยนต่อได้)* |
| `CANCELLED` | สีแดงเข้ม | ยกเลิกใบเคลม | *(สถานะสิ้นสุด ไม่สามารถเปลี่ยนต่อได้)* |

## 2 ช่องทางในการเปลี่ยนสถานะใบเคลมในระบบ

### ช่องทางที่ 1: ผ่านหน้าต่าง Claim Details Modal ใน Multi-Asset Claims Board (แนะนำ)
1. ในหน้า IT Portal เลื่อนไปที่ตาราง **Multi-Asset Claims Board**
2. คลิกปุ่ม **[📋 รายละเอียด]** ที่ใบเคลมที่ต้องการ
3. ระบบจะแสดงข้อมูลใบเคลม รายการเครื่อง และที่ด้านล่างจะมีปุ่มสถานะถัดไปที่อนุญาตให้กดเปลี่ยน เช่น:
   - `[➡️ เปลี่ยนเป็น SUBMITTED]`
   - `[➡️ เปลี่ยนเป็น RETURNED]`
   - `[➡️ เปลี่ยนเป็น CLOSED]`
   - `[➡️ ยกเลิก (CANCELLED)]`
4. เมื่อคลิกเปลี่ยนเป็น `RETURNED` หรือ `CLOSED` ระบบจะถาม:
   - ผลการเคลม: `Repaired` (ซ่อมเสร็จ) / `Replaced` (เปลี่ยนเครื่องใหม่) / `Scrapped` (แทงจำหน่าย)
   - หมายเหตุการเปลี่ยนสถานะ
5. ข้อมูลสถานะของใบเคลมและประวัติความปลอดภัยจะถูกอัปเดตทันที

---

### ช่องทางที่ 2: ผ่าน Action Board จากการสแกนเดี่ยว (Resolve RMA Modal)
เหมาะสำหรับการรับเครื่องคืนทีละชิ้นหน้าเคาน์เตอร์ IT:
1. สแกนรหัสครุภัณฑ์ที่มีสถานะ `Pending Pickup`
2. คลิกปุ่ม **[ตรวจสอบเครื่องและนำเข้าคลังปกติ (Return to Stock)]**
3. หน้าต่าง "บันทึกรับเครื่องคืนจากศูนย์บริการ" จะเปิดขึ้นมา ให้กรอก:
   - **ผลการซ่อม/เคลม:** ซ่อมแซมเรียบร้อย (Repaired) / ได้รับเครื่องทดแทนใหม่ (Replaced) / ซ่อมไม่ได้-จำหน่ายออก (Scrapped)
   - **Serial Number ใหม่:** กรอกหากได้เครื่องเปลี่ยนใหม่ทั้งชุด (ระบบจะอัปเดต S/N ให้อัตโนมัติ)
   - **ค่าใช้จ่ายในการซ่อม (บาท):** ระบุ `0` หากอยู่ในระยะรับประกัน
4. คลิก **[บันทึกรับเครื่องคืนและนำเข้าคลังปกติ]**
   - สถานะของครุภัณฑ์จะเปลี่ยนกลับเป็น `Working` พร้อมใช้งานทันที
   - บันทึกการเคลื่อนย้ายทิศทาง `IN` กลับเข้าแผนก

---

## กฎความปลอดภัยของ State Machine ใน Backend

- ทุกการเปลี่ยนสถานะต้องผ่านฟังก์ชัน `transitionClaimStatus()` ใน `services/claimService.js`
- หากมีการส่งสถานะที่ไม่อยู่ในรายการที่อนุญาต ระบบจะปฏิเสธด้วยรหัส HTTP `400 Bad Request` เช่น:
  ```json
  { "error": "Invalid state transition from DRAFT to CLOSED" }
  ```
- ทุกการเปลี่ยนสถานะจะบันทึก Audit Log เสมอเพื่อความโปร่งใส

# 12 — EOL & Salvage Actions (การจัดการครุภัณฑ์หมดสภาพและแทงจำหน่าย)

> **กลุ่มผู้ใช้:** IT Admin | **เวลาอ่าน:** ~5 นาที

---

## EOL คืออะไร?

**EOL (End of Life)** หมายถึง อุปกรณ์เทคโนโลยีสารสนเทศที่หมดอายุขัยการใช้งาน (Lifespan Exceeded) หรือผ่านการประเมินจากระบบแล้วพบว่ามีคะแนนความคุ้มค่าสูงกว่า 5.0 (`NOT_VIABLE`) ซึ่งการส่งซ่อมจะมีค่าใช้จ่ายสูงกว่ามูลค่าคงเหลือของอุปกรณ์ หรือไม่สามารถจัดหาอะไหล่ได้อีกต่อไป

ใน ClaimIT ฝ่าย IT สามารถบริหารจัดการวงจรชีวิตขั้นสุดท้ายของอุปกรณ์ได้อย่างถูกต้องตามระเบียบบริหารพัสดุและมาตรการควบคุมทรัพย์สินโรงพยาบาล

---

## ตัวเลือกการจัดการซากอุปกรณ์ (Salvage Action Options)

เมื่อเจ้าหน้าที่ IT สแกนครุภัณฑ์ที่มีสถานะ `Broken` หรือประเมินว่า `NOT_VIABLE` แผง **"EOL Salvage Actions Panel"** จะปรากฏขึ้นใน Action Board พร้อม 3 ตัวเลือกหลัก:

### 1. รอขายทอดตลาด (Pending Sell)
- **ความเหมาะสม:** อุปกรณ์ยังมีชิ้นส่วนที่ใช้งานได้ หรือมีมูลค่าซากที่สามารถเปิดประมูล/ขายต่อเพื่อนำเงินกลับเข้ากองทุนโรงพยาบาล
- **การดำเนินการ:** คลิกปุ่มสีม่วง `[💰 รอขายทอดตลาด (Pending Sell)]`
- **สถานะ:** 
  - `status` เปลี่ยนเป็น `Pending Sell`
  - `salvage_status` เปลี่ยนเป็น `Pending Sell`
- **เมื่อดำเนินการขายเสร็จสิ้น:** ระบบสามารถปรับสถานะขั้นสุดท้ายเป็น `Sold` (ขายทอดตลาดแล้ว)

### 2. รอดำเนินการบริจาค (Pending Donation)
- **ความเหมาะสม:** อุปกรณ์ที่ยังใช้งานพื้นฐานได้ แต่อาจไม่เพียงพอสำหรับโปรแกรมทางการแพทย์ในโรงพยาบาล สามารถส่งมอบให้สถานศึกษา โรงเรียน หรือมูลนิธิ
- **การดำเนินการ:** คลิกปุ่มสีชมพู `[🎁 รอดำเนินการบริจาค (Pending Donation)]`
- **สถานะ:**
  - `status` เปลี่ยนเป็น `Pending Donation`
  - `salvage_status` เปลี่ยนเป็น `Pending Donation`
- **เมื่อส่งมอบเรียบร้อย:** ระบบสามารถปรับสถานะขั้นสุดท้ายเป็น `Donated` (บริจาคเรียบร้อย)

### 3. แทงจำหน่าย / ทิ้งเป็นขยะอิเล็กทรอนิกส์ (Scrapped)
- **ความเหมาะสม:** อุปกรณ์ที่ชำรุดเสียหายสิ้นเชิง เมนบอร์ดไหม้ แตกหักจนซ่อมไม่ได้ และไม่มีมูลค่าซาก
- **การดำเนินการ:** คลิกปุ่มสีเทาเข้ม `[🗑️ แทงจำหน่าย (Scrap)]`
- **สถานะ:**
  - `status` เปลี่ยนเป็น `Scrapped`
  - `salvage_status` เปลี่ยนเป็น `Scrapped`

## ตารางสรุปค่าสถานะ Salvage ในระบบ

| ค่า `salvage_status` | ค่า `status` ในตาราง `mains` | ป้ายสีที่แสดงในตาราง (Badge) |
|---|---|---|
| `None` | `Working` / `Broken` | ตามสถานะการทำงานปกติ |
| `Pending Sell` | `Pending Sell` | `<span class="badge badge-sell">💰 รอขายทอดตลาด</span>` |
| `Sold` | `Sold` | `<span class="badge badge-sell">💰 ขายทอดตลาดแล้ว</span>` |
| `Pending Donation` | `Pending Donation` | `<span class="badge badge-donation">🎁 รอดำเนินการบริจาค</span>` |
| `Donated` | `Donated` | `<span class="badge badge-donation">🎁 บริจาคเรียบร้อย</span>` |
| `Scrapped` | `Scrapped` | `<span class="badge badge-scrapped">🗑️ แทงจำหน่าย (Scrapped)</span>` |

## การทำงานฝั่งเซิร์ฟเวอร์ (Backend Processing)

เมื่อมีการส่งคำขอผ่าน `POST /api/assets/salvage`:
```json
{
  "asset_tag": "CIT-2021-AIO-01",
  "salvage_status": "Pending Sell",
  "action_by_username": "admin"
}
```

ระบบจะดำเนินการ:
1. อัปเดตฟิลด์ `salvage_status` และ `status` ในตาราง `mains` ให้ตรงกัน
2. บันทึกเหตุการณ์ลงใน `move_log` เพื่อเป็นหลักฐาน Audit:
   - `department_name`: `'Salvage Dept'`
   - `floor`: `'Warehouse'` (คลังพักซากพัสดุ)
   - `moved_direction`: `'OUT'` (ตัดจำหน่ายออกจากพื้นที่ใช้งาน)
   - `details`: `'จัดการแทงจำหน่าย/บริจาค: [salvage_status]'`
3. ตอบกลับสถานะสำเร็จและสร้างรหัสติดตาม `log_code` อัตโนมัติ

## การติดตามและการกรองในตารางคลังครุภัณฑ์

เจ้าหน้าที่พัสดุและหัวหน้าฝ่าย IT สามารถตรวจสอบทรัพย์สินรอจำหน่ายได้โดย:
1. ไปที่ตาราง **คลังครุภัณฑ์ทั้งหมด (Asset Inventory)**
2. คลิกตัวกรองสถานะ (Status Filter) เลือก:
   - *"รอขายทอดตลาด"*
   - *"รอดำเนินการบริจาค"*
   - *"แทงจำหน่าย (Scrapped)"*
3. สามารถคลิก **[ส่งออก Excel ทั้งหมด]** เพื่อจัดทำรายงานเสนอต่อคณะกรรมการพัสดุโรงพยาบาลได้ทันที

  • 03. สแกนและค้นหาครุภัณฑ์ขั้นสูง: Hardware Burst Listener, Anti-Typo Engine และ Offline Barcode Engine

  • 05. มาตรการความปลอดภัยข้อมูล PDPA Storage Sanitization: ประตูกักกันข้อมูล (Enforced Wipe Gate: พิมพ์ "ยืนยัน" / "WIPED")

  • 07. เครื่องคำนวณความคุ้มค่า (Viability Score Engine): ดัชนีตัดสิน ≤ 5.0 (VIABLE) vs > 5.0 (NOT_VIABLE)
  • 08. วงจรสถานะงานเคลม (6-Stage Claim State Machine): DRAFT → CONFIRMED → SUBMITTED → VENDOR_RESPONSE → RETURNED → CLOSED
  • 09. ระบบจัดเก็บไฟล์หลักฐานและความปลอดภัย (Evidence Storage): IDOR Protection, Magic Byte Inspection และการกักกันไฟล์ 90 วัน
  • 10. ศูนย์พิมพ์เอกสารราชการและ PDF (PDF & Print Center): ใบส่งเคลม RMA Voucher, Gate Pass และ Repair Slips ฟอนต์ไทย Tahoma
  • 11. การแทงจำหน่ายและจัดการซาก (EOL & Salvage Disposal): Pending Sell, Sold, Pending Donation, Donated และ Scrapped
  • 12. บันทึกประวัติการเปลี่ยนแปลงแบบแก้ไขไม่ได้ (Audit Trail): รหัสอ้างอิง CHG-YYYYMMDD-XXXXXX และตัวกรองช่วงเวลา
  • 13. การบริหารจัดการบัญชีผู้ใช้ (User Management): แยกตาราง Admin/Staff, ตัวกรองบทบาท, นโยบายรหัสผ่าน must_change_password
  • 14. การตั้งค่าระบบ 6 แท็บย่อย (System Configurations): แบรนด์, หมวดหมู่เรียงตาม ID, ทะเบียนผังอาคารโรงพยาบาลถาวร, ผู้ใช้, Feedback & Bugs (#tab-cfg-feedback) และสำรองฐานข้อมูล

  • 16. การส่งออกข้อมูล Excel & CSV: Microsoft Excel SpreadsheetML (.xls) แบบหลายชีต และ UTF-8 BOM CSV
  • 17. เมนูทางลัดด่วน (Quick Access Sidebar Drawer): สถิติงานประจำวัน, ประวัติการสแกน และสายด่วน Vendor
  • 18. การแจ้งเตือนผ่านอีเมล (Email Notifications): Resend API Integration สำหรับรายงานผล Viability และใบเคลม
  • 19. มาตรการความปลอดภัยและป้องกันการโจมตี (Security & Hardening): Rate Limiting, CORS, Parameterized SQL, Token Revocation
  • 20. การติดตั้งระบบและการบำรุงรักษา (DevOps & Deployment): Node.js, Docker Compose, SQLite WAL Mode และ Daily Auto-Maintenance

💻 ภาพรวมหน้าจอศูนย์ควบคุมและตารางครุภัณฑ์ (IT Portal Admin UI)

2.1 การบริหารจัดการทะเบียนครุภัณฑ์ (Asset Management)

  • ตัวกรองหมวดหมู่ Dropdown Selector (filter-category-select): ออกแบบกะทัดรัด สะอาดตา อยู่เคียงข้างตัวกรองสถานะอุปกรณ์ ช่วยตัดปัญหา Horizontal Scrollbar กรองเฉพาะ Computer, Monitor, Printer, Network ได้ทันที
  • ระบบป้องกันการพิมพ์หลายยี่ห้อ (Single-Brand Guardrail): ตรวจสอบทั้ง Frontend และ Backend ป้องกันไม่ให้พิมพ์หลายยี่ห้อปนกัน (เช่น Dell และ Acer, HP, Lenovo) พร้อมระบบ Whitelist รองรับชื่อแบรนด์ผสมถูกต้อง เช่น A&D Medical, Bang & Olufsen, AT&T
  • ปุ่มสล็อตตัวเลขสลับหน้า (Numbered Pagination Slots): แสดงปุ่ม [1] [2] [3] ... ชัดเจน พร้อมระบบล็อกปุ่มขอบหน้า (Boundary Disabled)
  • 🏥 ทำเนียบผังอาคารโรงพยาบาลมาตรฐาน (Hospital Layout Picker): กดเลือกอาคาร ชั้น และแผนกจากผังโครงสร้างจริง (อาคาร 1 ชั้น 21 ถึง ชั้น D และอาคาร Call Center) ป้องกันข้อผิดพลาดในการพิมพ์ชื่อสถานที่

2.2 มาตรการความปลอดภัยข้อมูล PDPA (Enforced Wipe Gate)

🛑 ข้อบังคับความปลอดภัยข้อมูลผู้ป่วย (PDPA Data Sanitization Gate)
อุปกรณ์ที่มีสื่อบันทึกข้อมูล (ฮาร์ดดิสก์, SSD) เช่น คอมพิวเตอร์ All-in-One หรือโน้ตบุ๊ก จะถูกระบบบล็อกไม่ให้ออกใบส่งเคลมเด็ดขาด จนกว่าผู้ดูแลระบบจะยืนยันว่าได้ถอดสื่อบันทึกข้อมูลหรือทำการล้างข้อมูลความปลอดภัยเรียบร้อยแล้ว
  1. เปิดการ์ดรายละเอียดของเครื่องที่แจ้งซ่อม
  2. ติ๊กช่อง "ข้าพเจ้ายืนยันว่าได้ถอดสื่อบันทึกข้อมูล หรือล้างข้อมูลความปลอดภัยเรียบร้อยแล้ว"
  3. พิมพ์รหัสยืนยัน: ยืนยัน หรือ WIPED
  4. กดปุ่ม [ยืนยันความปลอดภัยข้อมูล] ระบบจะบันทึก Audit Log และปลดล็อกให้สามารถนำเครื่องเข้าสู่กระบวนการสร้างใบเคลม RMA ได้ทันที

2.3 การประเมินความคุ้มค่า (Viability Score Engine)

ระบบใช้สูตรคำนวณความคุ้มค่าทางเศรษฐศาสตร์:

  • อยู่ในสัญญาประกัน: Viability Score = 1.0 (VIABLE) (คุ้มค่าที่สุด ศูนย์บริการรับผิดชอบค่าอะไหล่และค่าแรง)
  • หมดประกันแล้ว: คำนวณจากราคาจัดซื้อเดิม, ค่าซ่อมประเมิน, และอายุการใช้งาน:
    • คะแนน 0.0 – 5.0 (🟢 VIABLE): คุ้มค่าส่งซ่อมศูนย์บริการ
    • คะแนน 5.1 – 10.0 (🔴 NOT VIABLE): ไม่คุ้มค่าซ่อม (เครื่องเก่าเกิน 5 ปี หรือค่าซ่อมเกิน 50% ของมูลค่าคงเหลือ) ควรพิจารณาเสนอแทงจำหน่าย (Scrap) หรือขายทอดตลาด

2.4 การสร้างใบส่งเคลมศูนย์บริการ (Multi-Asset RMA Claims)

  • กดปุ่ม [➕ สร้างใบเคลมใหม่] ในแท็บใบส่งเคลม
  • เลือกศูนย์บริการ (Vendor) เช่น Dell ProSupport, HP Care, TSC, Canon, Acer ฯลฯ และใส่เลข Case/Ticket
  • สามารถเลือกครุภัณฑ์ที่ผ่านการล้างข้อมูลแล้วรวมส่งพร้อมกันได้ 1 ถึง 5 เครื่องต่อ 1 ใบเคลม
  • เมื่อบันทึก เครื่องจะเปลี่ยนสถานะเป็น Pending Pickup (รอรถขนส่งมารับ)

2.5 วงจรสถานะงานเคลม (6-Stage Claim State Machine)

ลำดับสถานะความหมายและเงื่อนไขการเปลี่ยนผ่าน
1DRAFTร่างใบเคลม ยังสามารถเพิ่ม/ลดรายการครุภัณฑ์ได้
2CONFIRMEDยืนยันรายการส่งซ่อม ล็อกรายการครุภัณฑ์
3SUBMITTEDส่งมอบเครื่องให้รถขนส่ง/ศูนย์บริการเรียบร้อยแล้ว
4VENDOR_RESPONSEศูนย์บริการตอบรับ กำลังดำเนินการซ่อมหรือรออะไหล่
5RETURNEDศูนย์บริการส่งเครื่องกลับมาถึงโรงพยาบาล อยู่ระหว่างตรวจรับ
6CLOSEDตรวจรับเรียบร้อย ส่งเครื่องคืนวอร์ด ปิดงานสมบูรณ์

2.6 การตั้งค่าระบบ 6 แท็บย่อย (System Configurations)

  1. 🏷️ แบรนด์ & คู่มือเคลม: บันทึกข้อมูลติดต่อและเงื่อนไขการส่งซ่อมของแต่ละศูนย์บริการ
  2. 💻 หมวดหมู่อุปกรณ์: จัดระเบียบตามลำดับ ID พร้อมคำแปลภาษาไทย
  3. 🏥 แผนกและผังอาคารถาวร (Hospital Directory): แสดงผังอาคารทางการ (อาคาร 1 และ Call Center) แบบไม่ให้ลบโครงสร้างถาวร
  4. 👥 จัดการบัญชีผู้ใช้ (RBAC): แยกตารางแสดงผล Admin และ Staff พร้อมปุ่มเปลี่ยนรหัสผ่านและนโยบาย must_change_password
  5. 💬 ข้อเสนอแนะและแจ้งปัญหา (Feedback & Bugs): ติดตามข้อเสนอแนะจากเจ้าหน้าที่หน้างาน (แท็บ #tab-cfg-feedback)
  6. 💾 สำรองฐานข้อมูล & สายด่วนไอที:
    • แก้ไขเบอร์สายด่วน IT Support Hotline: ระบุหมายเลขคั่นด้วยจุลภาค เช่น 4401, 4402, 4403 เพื่ออัปเดตไปยังหน้า Staff ทันที
    • สำรองฐานข้อมูล (SQLite Backup): คลิกเดียวเพื่อดาวน์โหลด Snapshot ฐานข้อมูลพร้อมโครงสร้างครบถ้วน

2.7 ความปลอดภัยและการจัดเก็บหลักฐาน (Evidence Storage & IDOR Protection)

  • Magic Byte Validation: ตรวจสอบโครงสร้างไบต์จริงของไฟล์ทุกไฟล์บนดิสก์ ป้องกันการปลอมแปลงนามสกุลไฟล์
  • IDOR Protection: การเข้าถึงไฟล์หลักฐานทุกไฟล์ต้องผ่านการตรวจสอบสิทธิ์ JWT และความสัมพันธ์ของคดี
  • Quarantine Purge: ระบบทำความสะอาดไฟล์ที่กักกันเกิน 90 วันอัตโนมัติทุก 24 ชั่วโมง

2.8 การติดตั้งและการบำรุงรักษา (DevOps & Maintenance)

  • คำสั่งเริ่มต้นระบบ: npm start หรือรันไฟล์ Start_Hospital_LAN.bat
  • การทำงานบนเครือข่ายแลนโรงพยาบาล: ระบบผูกกับ 0.0.0.0 และตรวจจับ IP วงแลน 10.33.x.x หรือ 10.x.x.x อัตโนมัติ
  • SQLite WAL Mode: เปิดใช้งาน Write-Ahead Logging เพื่อรองรับการอ่าน/เขียนพร้อมกันหลายแผนกได้อย่างมีเสถียรภาพ
